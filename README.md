# 📦 WarehouseApp

سیستم یکپارچهٔ **انبار، فروش، مشتریان، مالی و فروشگاه اینترنتی** — ساخته‌شده با **Blazor Web App (.NET 8)** و **SQL Server**، با رابط کاربری کامل فارسی، راست‌به‌چپ و تاریخ شمسی.

این برنامه هم برای استفادهٔ داخلی (انبار و دفتر) و هم برای فروش آنلاین طراحی شده است؛ یعنی هم انبار و حساب‌ها را می‌چرخاند و هم یک فروشگاه اینترنتی روی همان داده‌ها دارد.

## 🚀 اجرا

**گام ۱ — گرفتن مخزن:**

```powershell
git clone https://github.com/naderamani68/WarehouseApp.git
cd WarehouseApp
```

**گام ۲ — بررسی رشتهٔ اتصال** در `appsettings.json`:

```text
Server=localhost;Database=WarehouseAppDb;Trusted_Connection=True;TrustServerCertificate=True;
```

**گام ۳ — بازیابی بسته‌ها:**

```powershell
dotnet restore
```

اگر اینترنت نداری و بسته‌ها در کش موجودند:

```powershell
dotnet build --no-restore
```

**گام ۴ — ساخت پایگاه داده:**

```powershell
dotnet ef database update
```

**گام ۵ — اجرا:**

```powershell
dotnet run
```

**گام ۶ — اولین ورود:**

مرورگر را روی `http://localhost:5023` باز کن. چون هنوز کارمندی وجود ندارد، صفحهٔ **راه‌اندازی اولیه** می‌آید و حساب **مدیر سیستم** را می‌سازد. پس از آن این صفحه خودش بسته می‌شود.

## 🛒 فروشگاه اینترنتی چطور کار می‌کند؟

فروشگاه **عمداً ایستا** ساخته شده است؛ یعنی برای هر بازدیدکننده یک نشست سرور ساخته نمی‌شود. این کار فروشگاه را سبک و مقاوم می‌کند.

| موضوع | جزئیات |
|---|---|
| نمایش کالا | فقط کالاهای فعال و تیک‌خوردهٔ «نمایش در فروشگاه» |
| سبد خرید | کوکی با نام `WarehouseApp.Cart`، حداکثر ۳۰ قلم |
| ثبت سفارش | از طریق نقطه‌های پایانی سرور با توکن ضدجعل |
| قیمت | همیشه از پایگاه داده خوانده می‌شود، نه از فرم |
| نتیجه | سفارش **پیش‌نویس** در پنل با کانال «فروشگاه اینترنتی» |
| تأیید | با دکمهٔ «تأیید و کسر از انبار» در صفحهٔ سفارش‌های فروش |
| پیگیری | با شمارهٔ سفارش و تلفن ثبت‌شده |

## 🏬 کانال‌های فروش

هر سفارش می‌تواند مشخص کند کالا **کجا** فروخته شده است. هفت کانال پیش‌فرض:

```text
حضوری | تلفنی | دیوار | اینستاگرام | دیجی‌کالا | فروشگاه اینترنتی | سایر
```

- سفارش‌های سایت خودکار کانال «فروشگاه اینترنتی» می‌گیرند.
- کانال تازه را از `/crm/channels` خودت اضافه کن (مثلاً واتساپ یا تلگرام).
- کانالی که در سفارش‌ها استفاده شده باشد حذف نمی‌شود و فقط غیرفعال می‌شود، تا سابقه خراب نشود.

## 💰 گزارش سود

فرمول:

```text
سود = مبلغ فروش − (تعداد × بهای خرید کالا)
حاشیهٔ سود = سود ÷ مبلغ فروش × ۱۰۰
```

| نکته | توضیح |
|---|---|
| مبنا | فقط سفارش‌های **تأییدشده** |
| دو نما | به تفکیک کالا و به تفکیک کانال |
| بازه | تاریخ شمسی، با میانبر ۷ و ۳۰ و ۹۰ روز و از ابتدا |
| محدودیت | بهای تمام‌شده از «بهای خرید» فعلی کالا خوانده می‌شود |

⚠️ اگر بهای خرید کالایی صفر باشد، سود آن بیشتر از واقعیت نشان داده می‌شود. برای دقت بیشتر، بهای خرید همهٔ کالاها را از دکمهٔ «ورود قیمت‌ها» در صفحهٔ کالاها پر کن.

| `Sms.Enabled` | ارسال پیامک روشن یا خاموش |

## 💾 پشتیبان‌گیری

سرویس آن `Services/BackupService.cs` است، زمان‌بند خودکار `Services/BackupSchedulerService.cs` و اسکریپت زمان‌بندی `scripts/backup-database.ps1`.

پشتیبان‌گیری **دو بخش** دارد: پایگاه داده و عکس‌های کالا.

**راه اول — از خود برنامه:** منوی «مدیریت سیستم» ← «پشتیبان‌گیری» ← دکمهٔ «گرفتن پشتیبان الان».
پوشهٔ مقصد را همان‌جا تعیین می‌کنی. بار اول، برنامه خودش به حساب سرویس پایگاه داده اجازهٔ نوشتن روی آن پوشه را می‌دهد.

با روشن‌کردن گزینهٔ «پشتیبان‌گیری خودکار روزانه» و تعیین ساعت، برنامه هر روز خودش پشتیبان می‌گیرد.
اگر برنامه در آن ساعت خاموش باشد، اولین باری که روشن شد پشتیبان گرفته می‌شود.

**راه دوم — زمان‌بند ویندوز (برای وقتی برنامه خاموش است):** فایل `scripts/backup-database.ps1` را با زمان‌بند ویندوز هر شب اجرا کن:

```powershell
schtasks /Create /TN "WarehouseApp Backup" /TR "powershell -ExecutionPolicy Bypass -File <مسیر کامل اسکریپت>" /SC DAILY /ST 23:00 /RL HIGHEST
```

**گرفتن پشتیبان پایگاه داده:**

```sql
BACKUP DATABASE WarehouseAppDb
TO DISK = 'D:\Backup\WarehouseAppDb.bak'
WITH INIT, COMPRESSION;
```

**بازگرداندن پشتیبان** (اول برنامه را ببند):

```sql
RESTORE DATABASE WarehouseAppDb
FROM DISK = 'D:\Backup\WarehouseAppDb.bak'
WITH REPLACE;
```

**پشتیبان عکس‌ها:**

```powershell
Copy-Item -Path "wwwroot\uploads" -Destination "D:\Backup\uploads" -Recurse -Force
```

> ⚠️ پشتیبان پایگاه داده، عکس‌ها را شامل نمی‌شود. هر دو را با هم بگیر.
> ⚠️ پشتیبانی که بازیابی‌اش آزمایش نشده باشد، پشتیبان نیست. ماهی یک بار روی یک پایگاه دادهٔ آزمایشی بازیابی کن.

## 🔢 ورودی‌های استاندارد

| ورودی | قانون |
|---|---|
| شمارهٔ همراه | ۱۱ رقم، شروع با ۰۹ |
| رقم فارسی | خودکار به رقم لاتین تبدیل می‌شود |
| مبلغ | با جداکنندهٔ سهرقمی نقطه‌دار: ۲۰۰.۰۰۰ |
| اعشار مبلغ | پشتیبانی نمی‌شود — مبالغ تومان و ریال صحیح‌اند |
| فیلدهای عددی | فقط رقم؛ حرف تایپ نمی‌شود |
| نمایش مبلغ | با جداکنندهٔ نقطه‌دار: ۲۵۰.۰۰۰.۰۰۰ |

**شمارهٔ همراه** در چهار جا بررسی می‌شود: فرم مشتریان، مشتری سریع در فرم سفارش فروش، تسویه فروشگاه اینترنتی و پیگیری سفارش.
اگر شماره کوتاه یا بدون ۰۹ باشد، همان‌جا پیام خطا نشان داده می‌شود و ذخیره انجام نمی‌شود.

**مبلغ** در هشت فیلد جداکننده دارد: قیمت فروش و بهای خرید کالا، قیمت واحد و تخفیف اقلام سفارش، مبلغ هزینه، مبلغ چک، بدهی و پرداختی، مبلغ فرصت فروش.
نوشتن `۲۰۰۰۰۰` یا `200.000` یا `۲۰۰.۰۰۰` هر سه یک نتیجه دارند.

**کارت سفارش‌های در انتظار** در صفحهٔ خانه تعداد سفارش‌های پیش‌نویس را نشان می‌دهد؛ با کلیک روی آن، فهرست سفارش‌ها با فیلتر «پیش‌نویس» باز می‌شود.

**فیلدهای عددی** فقط رقم می‌پذیرند و حرف در آن‌ها تایپ نمی‌شود: تعداد و درصد تخفیف اقلام سفارش، تعداد حرکات انبار، ترتیب کانال فروش، روز نگهداری و ساعت پشتیبان‌گیری، کد ملی، کد اقتصادی، کد پستی، شمارهٔ سند، درصد فرصت فروش، تعداد هزینه و حد سفارش کالا. رقم فارسی هم خودکار به رقم لاتین تبدیل می‌شود.

## 🗂 دسته‌بندی درختی فروشگاه

دسته‌ها حالا می‌توانند **دستهٔ مادر** داشته باشند. در صفحهٔ «دسته‌بندی محصولات» فیلد «دستهٔ مادر» را انتخاب کن؛ اگر خالی بگذاری، دسته اصلی می‌ماند.

در فروشگاه این ساختار این‌طور دیده می‌شود:

| بخش | کار |
|---|---|
| نوار کناری | درخت دسته‌ها با شمارش کالا |
| کارت دسته‌ها | دسته‌های اصلی، در صفحهٔ اول |
| زیردسته‌ها | با کلیک روی دستهٔ مادر، دکمه‌های زیردسته‌ها می‌آید |
| کالاها | کالاهای خود دسته و همهٔ زیردسته‌هایش |
| گروه‌بندی | در صفحهٔ اول، کالاها دسته‌دسته نشان داده می‌شوند |

نمونه: «لوازم کامپیوتری» ساخته می‌شود، بعد «مانیتور» با دستهٔ مادر «لوازم کامپیوتری» ثبت می‌شود. در فروشگاه، کلیک روی «لوازم کامپیوتری» هم مانیتورها را نشان می‌دهد و هم دکمهٔ «مانیتور» را می‌سازد.

## 🧹 پاک‌کردن دادهٔ آزمایشی

پیش از استفادهٔ واقعی، داده‌های آزمایشی را با این اسکریپت پاک کن (پنجرهٔ فرمان در پوشهٔ پروژه):

```
powershell -ExecutionPolicy Bypass -File scripts\reset-data.ps1
```

این دستور سفارش‌ها، حرکات انبار، چک، بدهی، هزینه‌ها، پیگیری‌ها، فرصت‌های فروش، پیامک‌ها و تاریخچهٔ عملیات را پاک می‌کند و کالا و دسته و انبار و طرف حساب را نگه می‌دارد.

برای پاک‌کردن کالا و دسته و انبار و طرف حساب هم:

```
powershell -ExecutionPolicy Bypass -File scripts\reset-data.ps1 -All
```

حساب کارمندان، نقش‌ها، کانال‌های فروش و تنظیمات همیشه می‌مانند. اسکریپت پیش از پاک‌کردن، تعداد ردیف‌ها را نشان می‌دهد و تأیید می‌گیرد. برای اجرای بدون پرسش، `-Force` را اضافه کن.

### پاک‌سازی از داخل خود برنامه

به‌جای اجرای اسکریپت، می‌شود از صفحهٔ «نگهداری سیستم» هم استفاده کرد:

| ویژگی | توضیح |
|---|---|
| نشانی | منوی «مدیریت سیستم» → «نگهداری سیستم» |
| چه کسی می‌بیند | فقط نقش دارای اختیار نگهداری سیستم |
| انتخاب | تیک‌زدنی — هر بخش جدا؛ وابستگی‌ها خودکار تیک می‌خورند |
| تأیید | رمز عبور مدیر دوباره پرسیده می‌شود |
| پشتیبان | پیش از پاک‌سازی خودکار گرفته می‌شود؛ اگر نشد، پاک‌سازی متوقف می‌شود |
| ایمنی | کل کار در یک تراکنش؛ اگر خطایی بدهد هیچ‌چیز پاک نمی‌شود |

بخش‌های قابل انتخاب: سفارش‌های فروش، حرکات انبار، اسناد مالی، پیگیری و فرصت فروش، مشتریان و تأمین‌کنندگان، کالا و دسته و انبار، پیامک و تاریخچهٔ عملیات.

همیشه دست‌نخورده می‌مانند: حساب کارمندان، نقش‌ها و دسترسی‌ها، کانال‌های فروش و تنظیمات.

### وارد کردن از اکسل

| بخش | ستون‌ها به ترتیب | قالب نمونه |
|---|---|---|
| کالاها | کد · نام · واحد · قیمت فروش · بهای خرید · موجودی · حد سفارش · دسته | دکمهٔ «نمونهٔ کالاها» |
| قیمت‌ها | کد · نام · قیمت فروش · بهای خرید | دکمهٔ «نمونهٔ قیمت‌ها» |
| طرف حساب‌ها | کد · نام · نوع · شخص رابط · تلفن · موبایل · ایمیل · کد ملی · کد اقتصادی · شهر · نشانی · کد پستی · یادداشت | دکمهٔ «نمونهٔ اکسل» |
| دسته‌بندی‌ها | نام دسته · دستهٔ مادر · توضیح | دکمهٔ نمونه در صفحهٔ دسته‌بندی‌ها |

رفتار برنامه: کد تکراری به‌روزرسانی می‌شود، سطر بی‌نام رد می‌شود، موبایل نامعتبر رد می‌شود،
دستهٔ نانوشته ساخته می‌شود، و ردیف اول باید عنوان ستون‌ها باشد.

### خروجی اکسل

| ویژگی | توضیح |
|---|---|
| عدد واقعی | مبلغ و تعداد به‌صورت عدد ذخیره می‌شوند و در اکسل جمع می‌خورند |
| جمع کل | یک ردیف جمع در پایین هر خروجی با فرمول `SUM` |
| متن‌های حساس | موبایل و کد کالا متن می‌مانند تا صفر اول حذف نشود |
| رقم فارسی | مبلغ فارسی‌نویسی‌شده هم به عدد تبدیل می‌شود |

### بازیابی از داخل برنامه

در صفحهٔ «پشتیبان‌گیری»، بخش «بازیابی از پشتیبان»:

| ویژگی | توضیح |
|---|---|
| انتخاب نسخه | فهرست فایل‌های پشتیبان همراه تاریخ |
| تأیید | رمز عبور مدیر |
| پشتیبان امن | پیش از بازیابی، خودکار از وضعیت فعلی پشتیبان گرفته می‌شود |
| بررسی سلامت | فایل پیش از بازیابی بازبینی می‌شود |
| پس از بازیابی | یک‌بار خروج و ورود دوباره |

دستور دستی `RESTORE DATABASE` هم برای مواقع اضطراری در همان کادر، زیر «روش دستی»، نگه داشته شده است.

### ثبت تلاش‌های ورود ناموفق

هر ورود ناموفق در «تاریخچهٔ عملیات» ثبت می‌شود: نام کاربری، زمان و نشانی شبکه. رمز عبور هیچ‌وقت ذخیره نمی‌شود.

## 🧑‍💻 نکات مهم توسعه

| نکته | توضیح |
|---|---|
| کدگذاری فایل | فایل‌های `.razor` و `.cs` با متن فارسی باید UTF-8 با امضای BOM ذخیره شوند |
| پایان خط | فایل‌های متنی روی ویندوز با پایان خط ویندوزی ذخیره شوند تا هشدار گیت و ویژوال استودیو نیاید |
| حالت تعاملی | هر صفحهٔ تعاملی باید `@rendermode InteractiveServer` داشته باشد |
| فروشگاه ایستا | صفحه‌های فروشگاه تعاملی نیستند و نوشتن‌ها با نقطه‌های پایانی سرور انجام می‌شود |
| توکن ضدجعل | در هر فرم نقطهٔ پایانی، `<AntiforgeryToken />` لازم است |
| تاریخ | در فرم‌ها از کامپوننت `PersianDateInput` استفاده کن، نه `input type="date"` |
| پرس‌وجوی EF | ترتیب و فیلتر را روی ستون‌های واقعی بزن، بعد در حافظه به شیء نمایشی تبدیل کن |
| اتصال پایگاه داده | از `localhost` استفاده کن، نه نام نمونه |
| بررسی دسترسی | همه‌جا از `AccessService` استفاده کن |
| صفحه‌های داده | `@inherits PageBase` و به‌جای `OnInitializedAsync` متد `OnPageInitializedAsync` |
| چیدمان | چیدمان و صفحه هم‌زمان رندر می‌شوند؛ پس پرس‌وجوی چیدمان باید از `IDbContextFactory` استفاده کند |
| مهاجرت | بعد از هر مهاجرت، پروژه را دوباره بساز، بعد `dotnet ef database update` بزن |
| خط فرمان SQL | برای جدول‌هایی که ایندکس شرطی دارند، `sqlcmd` را با `-I` اجرا کن |
| فایل‌های بارگذاری‌شده | پوشهٔ `wwwroot/uploads` در گیت نگه‌داری نمی‌شود |
