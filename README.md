# 📦 WarehouseApp — سیستم مدیریت انبار

یک برنامهٔ تحت وب برای مدیریت انبار با **ورود کاربران و سطوح دسترسی**، ساخته‌شده با **Blazor Web App (.NET 8)** و **SQL Server**، با رابط کاربری کامل فارسی و راست‌به‌چپ.

## 🎭 نقش‌ها و سطوح دسترسی

نقش‌ها **در پایگاه داده** ذخیره می‌شوند (نه در کد)، و مدیر سیستم می‌تواند آن‌ها را از صفحهٔ «نقش‌ها و دسترسی‌ها» تغییر دهد.

**چهار نقش پیش‌فرض:**

| نقش | توضیح |
|---|---|
| مدیر سیستم | دسترسی کامل — و همیشه همهٔ اختیارات، شامل اختیاراتی که در آینده اضافه می‌شوند |
| مدیر انبار | همهٔ عملیات انبار و گزارش‌ها، بدون مدیریت کارمندان |
| انباردار | ثبت حرکات، مدیریت محصولات و دیدن گزارش‌ها |
| بازدیدکننده | فقط مشاهده |

**۱۳ اختیار قابل تیک‌زدن:** دیدن اطلاعات، مدیریت محصولات، حذف محصول، مدیریت دسته‌بندی‌ها، حذف دسته‌بندی، مدیریت انبارها، حذف انبار، ثبت حرکات انبار، خروجی اکسل، دیدن گزارش‌ها، دیدن تاریخچهٔ عملیات، مدیریت کارمندان، مدیریت نقش‌ها.

> 🔒 اختیارات **در خود کد** بررسی می‌شوند (نه فقط پنهان‌کردن دکمه) و **هر بار از پایگاه داده** خوانده می‌شوند؛ پس تغییر اختیارات، همان لحظه اثر می‌کند.

## 🚀 اجرا

**گام یک — گرفتن مخزن:**

```powershell
git clone https://github.com/naderamani68/WarehouseApp.git
cd WarehouseApp
```

**گام دو — بررسی رشتهٔ اتصال پایگاه داده** در فایل زیر:

```
appsettings.json
```

مقدار پیش‌فرض:

```
Server=localhost;Database=WarehouseAppDb;Trusted_Connection=True;TrustServerCertificate=True;
```

**گام سه — ساخت پایگاه داده:**

```powershell
dotnet restore
dotnet ef database update
```

**گام چهار — اجرا:**

```powershell
dotnet run
```

**گام پنج — اولین ورود:**

در مرورگر `http://localhost:5023` را باز کنید. چون هنوز هیچ کارمندی وجود ندارد، صفحهٔ **«راه‌اندازی اولیه»** نمایش داده می‌شود و از شما می‌خواهد حساب **مدیر سیستم** را بسازید.

پس از آن، این صفحه **خودش را می‌بندد** و دیگر کسی نمی‌تواند از آن سوءاستفاده کند.

## ⚠️ نکات مهم توسعه

- فایل‌های `.razor` و `.cs` که متن فارسی دارند باید با **UTF-8 with BOM** ذخیره شوند.
- هر صفحهٔ تعاملی باید `@rendermode InteractiveServer` داشته باشد.
- در اتصال به SQL Server از `localhost` استفاده کنید، نه نام نمونه.
- برای هر بررسی دسترسی، از `AccessService` استفاده کنید (اختیارات از پایگاه داده خوانده می‌شوند).
- در صفحه‌های داده، `@inherits PageBase` بگذارید و به‌جای `OnInitializedAsync` متد `OnPageInitializedAsync` را بنویسید.
- **چیدمان و صفحه هم‌زمان رندر می‌شوند**؛ پس هر پرس‌وجوی پایگاه داده در چیدمان باید از `IDbContextFactory` استفاده کند، وگرنه خطای «دو عملیات هم‌زمان» رخ می‌دهد.
- بعد از هر مهاجرت جدید، پروژه را **دوباره build کنید** و روی یک پایگاه دادهٔ خالی هم آزمایش کنید.
